# tdnet-watch

TDnet（適時開示）を15分おきに監視し、**好材料 × 上昇トレンドのチャート** が揃った日本株だけを Slack / Discord / LINE に通知する最小構成ツール。GitHub Actions の無料枠で常駐する。

```
TDnet一覧HTML ─→ キーワード一次判定 ─→ (方向不明ならPDF本文で上方/下方推定) ─→ yfinanceでチャート条件 ─→ 通知
                                        └─ ANTHROPIC_API_KEY があれば Claude が最終判定（任意）
                                                        通知には教材由来の判断材料を併記 ──┘
                                                        （ステージ／ダウ理論／節目／地合い／決算接近）
```

監視とは別に、銘柄コード（トヨタなら `7203`）を入力してその銘柄の現在状況を通知先へ送る手動照会もできる（→ [銘柄コードを指定して状況を照会する](#銘柄コードを指定して状況を照会する)）。

さらに 1日1回・引け後（JST 16:35）に、**材料ニュースが無くても教材条件（上昇トレンド・追随期・25MA上向き・地合い良好）を満たした銘柄**を日経225から拾って通知する（→ [教材条件スキャン](#教材条件スキャン材料ニュース無しの通知枠)）。同じタイミングで、その日の稼働結果を伝える[日次サマリ](#日次サマリ)も届く。

逆方向の枠として、場中に **悪材料が無いのに急落した銘柄**（誤発注・パニック売り・口座乗っ取りの投げ売り・不正アクセスやシステム障害の開示など、一時的とみなせる下げ）を拾う急落検知もある。「戻りを期待できる下げ」だけを通知する（→ [急落検知](#急落検知一時的な下げからの戻りを狙う枠)）。

「何円まで上がる」という予想は出さない。出すのは **見送り条件・損切り目安・次の節目（上値抵抗＝利確目安）** まで。

## セットアップ（30分）

### 1. リポジトリを作る
このフォルダをそのまま GitHub の新規リポジトリに push する。**Public 推奨**（Actions の実行時間が無制限。Private でも月2,000分あるので足りる）。

### 2. 通知先を決めて Secrets に登録
リポジトリの **Settings → Secrets and variables → Actions → New repository secret**。

必要なものだけ登録すればよい。**登録した通知先すべてに送る**（Slack と Discord の両方に、なども可）。
ひとつも登録しなければ Actions のログに出るだけで、その状態でも安全に動く。

| Secret 名 | 用途 | 必要性 |
|---|---|---|
| `SLACK_WEBHOOK_URL` | Slack Incoming Webhook。**一番簡単。まずこれを推奨** | 通知先はどれか1つあればよい |
| `SLACK_BOT_TOKEN` ＋ `SLACK_CHANNEL` | Slack Bot。Webhook を禁止しているワークスペース向け | 〃 |
| `DISCORD_WEBHOOK_URL` | Discord Webhook | 〃 |
| `LINE_CHANNEL_ACCESS_TOKEN` ＋ `LINE_USER_ID` | LINE Messaging API push（無料枠 月200通） | 〃 |
| `NOTIFY_WEBHOOK_URL` | 自作APIなど任意のURLへ `{"text": "..."}` を JSON POST | 〃 |
| `ANTHROPIC_API_KEY` | Claude が「業績予想の修正」の方向と材料の強弱を判定 | 任意（1判定 ≒ 0.3円） |

Secret は登録後に中身を再表示できない。控えは手元に残しておくこと。

#### Slack : Incoming Webhook（所要3分・推奨）

1. https://api.slack.com/apps → **Create New App** → **Blank app**（旧「From scratch」。AI agent / Starter app は不要な機能が付くので選ばない）→ 名前 `tdnet-watch`、ワークスペースを選択
2. 左メニュー **Incoming Webhooks** → **Activate Incoming Webhooks** を On
3. 下部の **Add New Webhook to Workspace** → 通知先チャンネルを選んで **許可する**
4. 生成された `https://hooks.slack.com/services/T.../B.../...` をコピー
5. GitHub に Secret 名 `SLACK_WEBHOOK_URL` で登録

このURLを知っていれば誰でもそのチャンネルに投稿できる。**コードに直書きせず必ず Secret に入れる。**

#### Slack : Bot token（Webhook が使えない場合）

アプリ作成（Blank app）までは同じ。そのあと：

1. 左メニュー **OAuth & Permissions** → Scopes → **Bot Token Scopes** に `chat:write` を追加
2. ページ上部 **Install to Workspace** → 許可 → `xoxb-` で始まる **Bot User OAuth Token** をコピー → Secret `SLACK_BOT_TOKEN`
3. Slack で通知先チャンネルを開き `/invite @tdnet-watch` で Bot を招待する（**忘れると `not_in_channel` エラー**）
4. チャンネル名を右クリック → リンクをコピー → 末尾の `C0123ABCD` がチャンネルID → Secret `SLACK_CHANNEL`

#### Discord

サーバー設定 → 連携サービス → ウェブフック → 新しいウェブフック → チャンネルを選んで **ウェブフックURLをコピー** → Secret `DISCORD_WEBHOOK_URL`。

#### LINE

LINE公式アカウントを**通知専用に新規作成**し、Messaging API を有効化。LINE Developers で長期のチャネルアクセストークンを発行 → `LINE_CHANNEL_ACCESS_TOKEN`。チャネル基本設定の「あなたのユーザーID」→ `LINE_USER_ID`。自分のLINEでその通知用アカウントを友だち追加しておく。

無料枠は月200通。エルメ等で運用中のアカウントは配信数の枠を食うので使わない。

#### Anthropic（任意）

https://console.anthropic.com → API Keys → Create Key → Secret `ANTHROPIC_API_KEY`。
未設定でも動く（キーワード＋PDF本文のヒューリスティックで判定）。

### 3. 動作確認

**通知先の設定確認（休場日でもできる）**

Actions タブ → `tdnet-watch` → **Run workflow** → **`test_notify` にチェック** → 実行。
テスト通知が1件飛ぶだけなので、Secret が正しく登録できているかを平日を待たずに確認できる。

**通常の動作確認**

同じく Run workflow（チェックなし）。平日 9:00〜18:00 JST ならその日の開示を実際に処理する。
**休場日は「休場日。終了」と出て通知処理まで到達しない**ので、Slack に何も来なくても正常。
休場日に一連の流れを流したいときは `force` にチェック（ただし当日株価が無いためチャート条件は全件落ちる）。

**引け後の日次処理を手で流す**

Run workflow → **`daily` にチェック**。教材条件スキャン（日経225）と日次サマリが動く。
日経225を全部読むので数分かかる。

ローカルで確認する場合:
```bash
pip install -r requirements.txt
python tests/test_basic.py                                          # ネット不要の単体テスト
python main.py --test-notify                                        # 通知先へテスト通知を1件送る
python main.py --test-notify --dry-run                              # 送らずに本文だけ確認
python main.py --sample sample/tdnet_sample.html --dry-run --no-state  # サンプル開示で一通り動かす
python main.py --dry-run --force                                    # 実際のTDnetを読む（通知はしない）
python main.py --stock 7203 --dry-run                               # 銘柄照会（送らず標準出力へ）
python main.py --scan-market --summary --dry-run --force            # 教材条件スキャン＋日次サマリ
python main.py --dip-scan --dry-run --force                         # 急落検知（場中でなくても回す。休場日は当日の足が無いので0件）
```

push や Pull Request のたびに CI（`.github/workflows/ci.yml`）が同じ単体テストを自動実行する。

### 4. 放置する
cron は平日 JST 9:03〜15:48 に15分おき、引け後は 16:03〜23:33 に30分おきで動く。
場中の15分おき実行では[急落検知](#急落検知一時的な下げからの戻りを狙う枠)も一緒に回る（16:00 以降の実行では自動で外れる）。
加えて JST 16:35 の1回だけ、教材条件スキャンと日次サマリが走る（急落検知も引けの値で1回判定する）。
状態ファイル `state/seen.json` を bot が commit するので、同じ開示は二度通知されない。

## 銘柄コードを指定して状況を照会する

気になる銘柄のコードを入力すると、その銘柄の現在状況をまとめて **登録している通知先すべて**（Slack / Discord / LINE / `NOTIFY_WEBHOOK_URL` の自作API）へ送る。

**GitHub Actions から**: Actions タブ → `tdnet-watch` → **Run workflow** → `stock_codes` に `7203` と入力（複数は `7203,6758` のようにカンマ区切り）→ 実行。1〜2分で通知が届く。

**ローカルから**:
```bash
python main.py --stock 7203              # 通知先へ送る
python main.py --stock 7203 --dry-run    # 送らずに標準出力で確認
```

通知の中身:

```
 当日 高値 2,880 ／ 安値 2,790（前日比 −0.6%）／ 安値からの戻り率 100%
 トレンド 上昇（現在値>25MA>75MA）

 総合 ◎ 追い風（教材条件 5/5）

※判断材料であり売買の推奨ではない
```

- チャート条件の判定基準は監視と同じ（[判定ロジック](#判定ロジック)参照）。未達のときは理由（出来高不足・RSI過熱など）を列挙する。教材由来の判定（ステージ・節目・地合い・決算接近・総合）も同じ形式で併記される
- 開示行は当日＋前営業日の適時開示から拾う（無ければ「開示 なし」）
- 休場日・引け後は直近営業日の終値で表示する（`（08/29終値）` のように付記）。当日の足が無い日は `当日 高値／安値` の行を出さない

- コードは4桁。`130A` のような英字入りの新方式コードや、TDnet式の5桁（`72030`）も受け付ける
- 社名は yfinance 由来のため英語表記になる

## 判定ロジック

**ニュース（`config.py` で調整）**

- `POSITIVE_KEYWORDS`: 上方修正 / 増配 / 自己株式の取得 / 業務提携 / 株式分割 / TOB賛同 / 受注 など
- `AMBIGUOUS_KEYWORDS`: 「業績予想の修正」のように上下が分からないもの → PDF本文の「上方修正・上回る」と「下方修正・下回る」の出現数で推定。AI キーがあれば Claude が判定
- `SKIP_KEYWORDS`: 下方修正 / 減配 / 訂正 / 自社株買いの進捗報告 / 役員人事 / 決算短信 など → 無条件で捨てる

**チャート（yfinance 日足、20分遅延）**

| 条件 | 既定値 | 意図 |
|---|---|---|
| 現在値 > 25日MA > 75日MA | — | 上昇トレンド中の銘柄だけ。**教材条件スキャンでは `25MA > 75MA` だけ**（下記） |
| RSI14 < 70 | `RSI_MAX` | 過熱銘柄を追わない |
| 当日出来高 ≥ 20日平均 × 1.5 | `VOLUME_RATIO` | 材料に市場が反応しているか。場中は経過時間で按分。**引け後（15:30以降）は課さない**（下記） |
| 前日終値比 ≤ +5% | `MAX_GAP_PCT` | 大きく飛んだものは材料出尽くしで見送り |
| 前日終値比 ≤ +2% | `ENTRY_GAP_PCT` | これ以内なら「エントリー候補」、超えたら「様子見」 |
| 損切り目安 | 現在値 − 2×ATR14 | `ATR_STOP_MULT` |

条件未達の材料は `pending` として同日中（引け後開示は翌営業日中）15分ごとに再判定する。9:00 に出来高が足りなくても 9:30 に増えていれば通知される。

**出来高条件を引け後に課さない理由**: 15:30 以降に出た開示の「当日出来高」は、そのニュースが出る前に積み上がった数字でしかない。材料はまだ一度も売買されていないので 1.5 倍を超えようがなく、要求すると引け後〜夜間（JST 16:03〜23:33）の監視が構造的に必ず空振りする。出来高は数値として通知に表示するが、合否のゲートからは外す。RSI・ギャップ・25MA>75MA の高値掴みガードは引け後もそのまま効く。

同一銘柄が同じ日に複数の該当開示を出した場合（例: 「業務提携」と「特別利益」）、株価の取得も通知も1銘柄1回にまとめる。判定ラベルは `業務提携／特別利益` のように連結され、開示行と PDF リンクは件数ぶん並ぶ。

### 教材条件スキャン（材料ニュース無しの通知枠）

`--scan-market`。TDnet に材料が出ていなくても、教材条件を満たした銘柄を通知する。1日1回・引け後（JST 16:35）にだけ走る（教材条件は週足ピボットと日足の押し目で決まるので、日足が確定する前に何度も回しても結果は変わらない）。

**通知条件は4点**（`chart_context.scan_ok`）: 週足で上昇トレンド ／ ステージが追随期 ／ 25MA上向き ／ 地合い良好。

- **対象**: 日経225（`nikkei225.py` のスナップショット。`state/universe.txt` に1行1コードで書けばそちらが優先され、監視したい銘柄だけに絞れる）
- **地合いが「良好」でないと1件も出ない**。日経平均が 25MA を割っている間はこの枠の通知は止まる（教材: 指数の天井サイン中は新規買いを止める）。数週間まるごと0件になり得るが、日次サマリに件数が出るので動いていることは確認できる
- 一度通知した銘柄は `SCAN_COOLDOWN_DAYS`（既定3日）のあいだ再通知しない。同じ条件が数日続いても毎日は鳴らない

#### 出来高・「現在値>25MA」・上値余地をゲートにしない理由

教材の5項目とチャート条件をすべて課すと**実質1件も鳴らない**。合成株価3000件で測った成立率（地合い良好の日・229銘柄あたりの週件数）:

| ゲート | 成立率 | 週あたり |
|---|---|---|
| 全部課す（教材5/5＋チャート4条件） | 0.03% | 0.4件 |
| `現在値>25MA` を外す | 0.17% | 1.9件 |
| **＋上値余地も外す（既定）** | **0.50%** | **5.7件** |
| 追随期を外す | 1.43% | 16.4件 |

外した3つには、それぞれ論理的な理由がある。

- **出来高 ≥1.5倍**（`SCAN_REQUIRE_VOLUME`）: 材料が出ていない銘柄の出来高が平常なのは当たり前。しかも教材の「追随期＝押し目からの反発」は出来高が細る局面そのもの
- **現在値 > 25MA**（`SCAN_REQUIRE_ABOVE_MA25`）: **押し目＝直近平均より下に落ちてきた状態**なので、これを課すのは「押し目を買え」という教材と正面から矛盾する。実測では追随期になった銘柄の **84%** がこの条件だけで落ちていた。`25MA > 75MA`（中期の並び）は残すのでトレンドフィルタは効いたまま
- **上値余地 ≥5%**（`SCAN_REQUIRE_ROOM`）: 押し目から入る以上、直上の節目までの距離は銘柄ごとに大きく違う。一律で切らず、通知に数値を出して各自で判断する

RSI<70・ギャップ≤+5%・25MA>75MA の高値掴みガードは効いたまま。

#### リスクリワードとは

通知の1行:

```
 上値余地 +8.7%（4,480円まで 360円） ／ 損切りまで −4.4%（−180円） ／ リスクリワード 2.0
```

```
                上値余地(%)        (上値抵抗 − 現在値) ÷ 現在値
リスクリワード = ───────────── = ────────────────────────────────
              損切りまでの距離(%)   (現在値 − 損切り目安) ÷ 現在値
```

- **上値余地** = 現在値から**次の目立つ山**（週足ピボット高値＝教材の利確目安）までの距離。上に山が無ければ「新高値圏」で余地は青天井扱い
- **損切りまでの距離** = 現在値から `現在値 − 2×ATR14`（`ATR_STOP_MULT`）まで。ATR は日々の値動きの平均幅なので、**ボラティリティの高い銘柄ほど損切りが遠くなる**

つまり「**うまくいったら取れる値幅 ÷ 失敗したら失う値幅**」。リスクリワード 2.0 なら、利確目安まで届けば損切り幅の2倍が取れる。

**これが1を割ると、勝率が5割では負ける。** 損益分岐に必要な勝率は `1 ÷ (1 + リスクリワード)`:

| リスクリワード | 損益分岐に必要な勝率 | 意味 |
|---|---|---|
| 0.36（実測の中央値） | **74%** | 4回に3回当てないと負ける |
| 0.5 | 67% | |
| 1.0 | 50% | 勝率5割でトントン |
| 1.5 | 40% | |
| 2.0 | 33% | 3回に1回当たれば勝てる |
| 3.0 | 25% | |

手数料とスリッページを無視した数字なので、実際に必要な勝率はもう少し高い。また「利確目安まで必ず届く」前提でもないし、ギャップダウンで損切り目安どおりに切れるとも限らない。あくまで**通知を上から順に見るときの足切りの目安**として使う。

#### 通知が来たら上値余地を見る

上値余地をゲートから外した代償として、**伸びしろの薄い銘柄も通知に混ざる**。同じ実測（通過15件）での分布:

| 上値余地 | リスクリワード | 件数 |
|---|---|---|
| +4%以上 | 1.1〜1.9 | 3件 |
| +1〜4% | 0.4〜0.8 | 5件 |
| +1%未満 | 0.0〜0.2 | 7件 |

リスクリワードの**中央値は 0.36**（＝勝率74%が必要）、1.0以上は 15件中3件だけだった。通知は上値余地の大きい順に並ぶので、**上のほうだけ見て、リスクリワードが1を割るものは見送る**運用になる。余地の薄いものには `注意 真上に抵抗線（余地+x%）` も併記される。

うるさければ `config.py` の `SCAN_REQUIRE_ROOM = True` で上値余地 ≥5% をゲートに戻せる（週1.9件まで減る）。ただし次項のとおり、**足切りするなら上値余地%よりリスクリワードのほうが筋がいい**。

数値は合成株価によるシミュレーションなので絶対値は参考値。実際の株価は水平線を意識して動くぶん、追随期は乱数より起きやすいはず。

#### 【未実装・今後の改善案】上値余地%ではなくリスクリワードで足切りする

いま自動で足切りできるのは上値余地%（`SCAN_REQUIRE_ROOM`）だけだが、**足切りするならリスクリワードを直接見たほうがいい。上値余地%はボラティリティを織り込まないため。**

損切り幅（2ATR）は銘柄によってまったく違う。チャート条件を通った1259件の実測:

| | 最小 | 25% | 中央 | 75% | 最大 |
|---|---|---|---|---|---|
| 損切りまでの距離 | 1.3% | 3.4% | **4.9%** | 6.4% | 11.9% |

**9倍の開きがある。** だから「上値余地5%」は銘柄によって意味がまるで変わる。

| 上値余地 | 損切りまで | リスクリワード | |
|---|---|---|---|
| +4.5〜5.5% の中の1件 | −9.9%（高ボラ） | **0.48** | 余地5%あっても割に合わない |
| +4.5〜5.5% の中の1件 | −1.9%（低ボラ） | **2.39** | ほぼ同じ余地でも5倍おいしい |
| +2.5〜3.5% の中の1件 | −8.5% | 0.30 | |
| +2.5〜3.5% の中の1件 | −1.8% | **1.91** | 余地3%でも十分取りに行ける |

上値余地 ≥5% で切った場合に何が起きるか（同じ1259件）:

- 通す285件のうち **49件（17%）はリスクリワード1.0未満** — 割に合わないのに通してしまう
- 落とす974件のうち **75件（8%）はリスクリワード1.0以上** — 割に合うのに取り逃がす

**実装するなら** `config.py` に `SCAN_MIN_RR`（既定 0.0 = 無効）を足して `room_pct / risk_pct >= SCAN_MIN_RR` を判定する。`risk_pct` は `screener.Screen` の `price` と `stop` から出せる（`(price - stop) / price * 100`）。置き場所は2つ:

- `chart_context.scan_ok()` の中 — ゲート判定が1箇所にまとまるが、`Screen` を渡すシグネチャ変更が要る
- `main.scan_market()` の `scan_ok()` 判定の直後 — シグネチャは変えずに済むが、ゲートが2箇所に分かれる

新高値圏（上値抵抗なし＝余地が青天井）は `room_pct` が `None` になるので、無条件で通す扱いにする。

参考までに、教材ゲートを通った銘柄に対する `SCAN_MIN_RR` の効き:

| しきい値 | 通過 | 週あたり（229銘柄・地合い良好の日） |
|---|---|---|
| 0.0（現在＝無効） | 100% | 5.7件 |
| 0.5 | 42% | 2.4件 |
| **1.0** | **25%** | **1.4件** |
| 1.5 | 17% | 1.0件 |

この表の母数は12件と少ないので、比率は目安。

日経225の構成銘柄は入替がある。リストが古くなっても、外れた銘柄を1つ余計にスキャンするか、新しい銘柄を拾えないだけで壊れない（存在しないコードは「株価データ無し」として黙って飛ばし、件数をログに出す）。

### 急落検知（一時的な下げからの戻りを狙う枠）

`--dip-scan`。ここまでの枠が「上がっている株の好材料」を拾うのに対し、この枠はその裏返しで、**業績と関係ない理由で一時的に下げた株**を場中に拾う。誤発注・パニック売り・証券口座の乗っ取りによる投げ売り、不正アクセスやシステム障害の開示など、「下げたが会社の中身は変わっていない」場面を想定している。前提は「そういう下げは戻りやすい」だが、**必ず戻る保証は無い**。通知は判断材料であって推奨ではない。

場中の15分おき実行（JST 9:03〜15:48）に同居して毎回回る。夜間の実行では回さず、引けの判定は 16:35 の日次実行が教材スキャンの日足を使い回して1回だけ行う。

通知は2種類:

```
【急落検知（悪材料なし）】09/04 10:33
```

```
【一過性悪材料×急落】09/04 11:03
地合い 日経平均 良好（終値>25MA・25MA上向き）／ 本日 −0.4%

 株価 1,036円（前日終値 1,120円）

 損切り目安 1,010円（当日安値割れ・−2.5%）／ 戻り目標 前日終値 1,120円（+8.1%） ／ リスクリワード 3.2
```

**2つの入口**

| 枠 | 入口 | 対象 |
|---|---|---|
| 【急落検知（悪材料なし）】 | 値動きだけ。悪材料の開示が無いのに大きく下げた | 日経225（`state/universe.txt` があればそちら） |
| 【一過性悪材料×急落】 | TDnet に `DIP_TRANSIENT_KEYWORDS`（不正アクセス・サイバー攻撃・ランサムウェア・システム障害・誤発注・情報漏えい 等）の開示が出て、かつ大きく下げた | 開示を出した銘柄そのもの。ユニバースの外でも拾う（1回の実行で最大10銘柄） |

「ハッキング」は2通りあり、企業自身が不正アクセスを受けた開示は後者、証券口座の乗っ取りで持ち株が投げ売りされる値崩れは（開示が無いので）前者で拾う。

**ゲート（5条件。すべて満たすと通知）**

| 条件 | 既定値 | 意図 |
|---|---|---|
| 前日終値比 ≤ −5% | `DIP_DROP_PCT` | **現在値で判定する。** 届いた時点で戻り切っていれば鳴らない（今からでも取りに行ける下げだけ通知する） |
| 日経平均の当日騰落率との差 ≤ −3pt | `DIP_INDEX_DIFF_PT` | 全体が同じだけ下げた日は地合いの下げで、銘柄固有の異常ではない。**2024年8月5日のような全体暴落の日は1件も鳴らない** |
| 25MA > 75MA | — | 中期トレンドが上向きのうちの押し目だけ。下降トレンドの続きの下げは「一時的」ではない |
| 悪材料の開示が無い | `DIP_NEGATIVE_KEYWORDS` | 当日＋前営業日の TDnet に下方修正・特別損失・減損・訂正・希薄化 等が無い。**「業績予想の修正」は上方修正でも見送り**（好材料で下げた＝材料出尽くしで、戻りを期待する下げではない） |
| 決算発表の当日・翌日でない | `DIP_EARNINGS_KEYWORDS` | 当日＋前営業日に決算短信が出ていない、かつ yfinance の次回決算日が当日でない。決算の下げは業績そのものなので一時的ではない |

一過性の材料と本物の悪材料が同時に出ていれば、悪材料を優先して見送る（保守的）。

**併記（合否には使わない）**

- **当日安値と戻り率**: 戻り率 = (現在値 − 当日安値) ÷ (前日終値 − 当日安値)。誤発注やフラッシュクラッシュは長い下ヒゲになるので、戻り率が高いほど「一瞬の下げ」らしい。0% は安値に張り付いたまま（反発未確認）
- **出来高倍率・RSI・下げ幅のATR換算**: パニック売りの証跡。ATR換算は「普段の値動きの何倍下げたか」で、2〜3ATR 以上なら異常値
- **週足の節目・ステージ・決算接近**: 既存の教材判定をそのまま併記。下に支持線があるかを見る。押し目の枠ではないので `総合` の点数は出さない
- **損切り目安と戻り目標**: 損切りは**当日安値割れ**、戻り目標は**前日終値**。リスクリワードはこの2つまでの距離の比。戻り率が `DIP_BOUNCE_CONFIRM_PCT`（既定10%）未満のときは「反発未確認」として比を出さない（安値に張り付いた状態で計算すると損切り幅がほぼ0になり、比が意味を持たないため）

**同じ銘柄は `DIP_COOLDOWN_DAYS`（既定3日）のあいだ再通知しない。** 下げが続いても毎日は鳴らない。1日分の件数は日次サマリに出る。

#### 20分遅延の前提

株価は既存どおり yfinance の日足で、20分遅延。cron の遅れも加わるので、**下げてから15〜35分後に届く**。「下げた瞬間」は取れない。誤発注のように数分で戻る下げは、届いた時点で戻り切っていて（前日終値比が −5% を割り込まなくなって）鳴らないことがある。それは仕様で、「今からでも取りに行ける下げ」だけを通知する。

分足は取らない。当日の日足に高値・安値・現在値・出来高が入っているので、それだけで「当日安値からの戻り率」まで出せる。分足を取ると yfinance の負荷が数倍になる割に、20分遅延の前では得るものが少ない。

#### yfinance の負荷

場中は15分ごとに日経225の日足をまとめて取る（`DIP_HISTORY_PERIOD` で1年分に短縮。75MA・ATR・週足の節目には足りる）。1回あたり数十秒〜1分。Yahoo 側でレート制限にかかったときは `config.py` の `DIP_SCAN_UNIVERSE = False` にすると値動き検知だけ止まり、開示キーワード検知（数銘柄しか取らない）は動き続ける。

日経平均の当日値が取れない実行（寄付き前・休場日・指数データの遅延）は、指数との差が出せないので**何も取りに行かずにスキップ**する。日次サマリにその旨が出る。

#### 何を拾って何を拾わないか

- 拾う: 誤発注・アルゴの暴走・SNS発のデマによる投げ売り・口座乗っ取りによる不正売買での値崩れ・不正アクセスやシステム障害の開示による下げ
- 拾わない: 決算・下方修正・不祥事（訂正・不適切会計・行政処分）・希薄化・下降トレンドの続き・全体暴落の日

「悪材料の開示が無い」は TDnet に出ていないというだけで、**ニュースや SNS が理由の下げは区別できない**（証券会社のレーティング引き下げ、報道、大株主の売りなど）。通知が来たら下げの理由を自分で確認してから判断する。

### 教材由来の追加判定

チャート教材（水平ロールリバーサル手法）の判断基準を `chart_context.py` でコード化し、通知に併記する。
材料×チャートの通知では**合否には影響しない**（判断材料が増えるだけ）。
一方この5項目のうち4つ（上昇トレンド・追随期・25MA上向き・地合い良好）が、材料ニュース無しで通知する[教材条件スキャン](#教材条件スキャン材料ニュース無しの通知枠)の合否そのものになる。
しきい値は `config.py` で調整できる。

| 判定 | 内容 | 既定値 |
|---|---|---|
| 目立つ山・谷 | 週足ピボット（前後2週より高い/安い点）。日足だけの小さな山は無視 | `PIVOT_SPAN_W` |
| ダウ理論トレンド | 直近2つの目立つ高値・安値がともに切り上げ→上昇／切り下げ→下降 | — |
| ステージ | 先行期（買わない）／追随期（唯一の買い場）／利食い期（飛びつき注意）／中立（待機）に分類 → [ステージの4種類](#ステージの4種類投資初心者向け) | — |
| 水平ロールリバーサル | 抵抗線上抜け → **20営業日以上**（約1ヶ月）あけてライン±3%へ押し → 当日陽線で反発 → 追随期 | `PULLBACK_MIN_DAYS` `LINE_NEAR_PCT` |
| 上値余地 | 次の目立つ山（上値抵抗＝利確目安）までの距離。**+5%未満なら「真上に抵抗線」警告**（ライン際の買い禁止） | `RESISTANCE_ROOM_PCT` |
| 25MAの傾き | 5営業日前より下なら「25MA下向き」警告（下向きのラインタッチは買わない） | `MA_SLOPE_DAYS` |
| 地合い | 日経平均が 25MA上・上向きなら「良好」。週足ダブルトップ＋ネックライン割れは「悪化（天井サイン）」 | `MARKET_INDEX` `DOUBLE_TOP_TOL_PCT` |
| 決算接近 | 次回決算が**5営業日以内**なら「⚠決算またぎ回避」警告（決算ギャンブルしない） | `EARNINGS_WARN_DAYS` |
| 総合 | 上の5条件（上昇トレンド・追随期・25MA上向き・上値余地・地合い）の充足数を ◎○△▲ で表示 | — |

- `MARKET_FILTER_HARD = True` にすると、地合い「悪化」の間は合格銘柄も `pending` に保留する（教材: 指数の天井サイン中は新規買いを止める）。既定は `False`（併記のみ）
- 決算日と地合いは yfinance からのベストエフォット取得。取れないときはその行が出ないだけで通知は止まらない
- 教材の「目立つ山」「効いているライン」は本来裁量判定のため、ピボット幅・接近%は近似値。パラメータを変えて精度を見ながら調整する

#### ステージの4種類（投資初心者向け）

通知の `ステージ 利食い期` のような行は、**その銘柄が上昇のどのあたりにいるか**を自動判定したもの。
株価が上がっていくとき、値動きは「上がる/下がる」の2択ではなく、だいたい次の順番で進む。

```
先行期 ──→ 追随期 ──→ 利食い期 ──→（下げ）──→ 先行期 …
（準備中）  （唯一の買い場） （利益確定が出る）
```

同じ「上がっている株」でも、**どの時期にいるかで買っていいかどうかが正反対**になる。
電車にたとえると、先行期はまだ電車が来ていないホーム、追随期はドアが開いて乗り込む時間、利食い期は発車ベルが鳴った後の駆け込み乗車にあたる。

| ステージ | ひとことで言うと | 通知に出る理由（`stage_note`） | 初心者の行動 |
|---|---|---|---|
| **先行期** | まだ上がる準備の段階。上がるかどうか分からない | 「下降トレンド中は見送り・高値と安値が切り下げ」／「支持線に接近中・反発の確認待ち」 | **買わない**。反発を確認するまで待つ |
| **追随期** | 上昇が始まり、いったん下げた（押した）ところから反発した | 「押し目反発を確認・水平ロールリバーサル成立」 | **教材が認める唯一の買い場** |
| **利食い期** | すでに大きく上げた後。先に買っていた人が利益確定（利食い）を始める | 「新高値圏を上伸中・飛びつかず初押し待ち」／「ブレイク後○営業日・初押し20営業日以上待ち」 | **買わない**。持っているなら利確を考える |
| **中立** | どれにも当てはまらない待機状態 | 「押し目形成待ち」 | 何もしない。追随期になるのを待つ |

**「利食い期」は名前がまぎらわしい。** 「今から利食いできる（儲かる）期間」ではなく、**「すでに買っていた人が売り抜ける番」の期間**という意味。
これから買う側から見れば、いちばん高いところを買わされる（高値掴みする）危険な時期になる。だから通知にも `注意 飛びつき買い注意` が一緒に出る。

**利食い期と判定される2つのパターン**（`chart_context.analyze`）:

- **新高値圏を上伸中** — チャートが取得期間（既定5年）内の最高値を更新中。パッと見はいちばん強く見えるが、上に目標にできる節目が無く、どこまで上がるか誰にも分からない状態。教材では「飛びつかずに、一度下げた（初押し）ところを待つ」
- **ブレイク後○営業日** — 抵抗線を上に抜けたばかりで、まだ一度も押し目を作っていない。教材は「ブレイクから**20営業日（約1ヶ月）以上**あけてからの押し目」を条件にしているので、それ未満は待ちになる（`PULLBACK_MIN_DAYS`）

どちらも「悪い銘柄」という意味ではない。**上がってはいるが、入るタイミングが今ではない**というだけ。この後で押し目を作って反発すれば、同じ銘柄が `追随期` に変わって通知される。

**判定の順番**（上から順に当てはまった時点で確定する）:

1. 週足が下降トレンド → **先行期**
2. 押し目からの反発を確認（水平ロールリバーサル成立） → **追随期**
3. 抵抗線ブレイクから20営業日未満 → **利食い期**
4. 支持線＋3%以下まで下げている（まだ反発は確認できていない） → **先行期**
5. 新高値を更新中 → **利食い期**
6. どれでもない → **中立**

**なぜ利食い期でも通知が届くのか。**
[教材条件スキャン](#教材条件スキャン材料ニュース無しの通知枠)（材料ニュース無しの引け後の枠）は**追随期しか通知しない**。
一方、材料×チャートの通知と[銘柄コードの手動照会](#銘柄コードを指定して状況を照会する)では、ステージは**合否に使わず併記するだけ**なので、利食い期の銘柄も届く。
「好材料が出た。ただし今のチャート位置は飛びつき注意」という情報として読む。ステージだけで切らないのは、材料が出た事実そのものを消したくないため。

## 制限・注意

- **yfinance は非公式 API。** Yahoo 側の仕様変更やレート制限で止まることがある。止まったら `pip install -U yfinance`。GitHub の IP がブロックされたときは `MAX_SCREEN_PER_RUN` を下げる。場中15分ごとの急落検知が日経225をまとめて取るぶん負荷が増えているので、詰まったら `DIP_SCAN_UNIVERSE = False` で先にそちらを止める
- **TDnet に公式 API は無い。** 一覧ページの HTML を読んでいるので、マークアップが変わったら `tdnet.py` の `parse_list()` を直す。一覧の各行は「時刻が `HH:MM`・銘柄コードが4〜5文字」を満たすものだけを開示として取り込む（ページ末尾の `Copyright © Tokyo Stock Exchange…` のようなフッター行も `<td>` が4つ以上あるため、行数だけでは区別できない）。コードや時刻の書式が変わって開示行を1件も認識できなくなった場合は、`[tdnet] …マークアップ変更の可能性` がログに出る
- GitHub Actions の cron は混雑時に5〜15分遅れる。「開示の瞬間」は取れない前提（そもそも20分遅延の株価なので同じ）
- 18:00 以降の開示は翌朝 9:00 の初回実行で拾う（前営業日 15:00 以降の開示を持ち越す仕様）
- 引け後の再実行は**同じ日足を読み直すだけ**なので判定結果は変わらない。夜間に何度動いても新しい開示が出ない限り通知は増えない（これは仕様。動いた事実は日次サマリで分かる）
- yfinance が一時的に落ちて株価を取れなかった銘柄は `skipped` になり、その開示はもう再判定されない（ETF・REIT を毎回引き直さないための割り切り）
- ETF / REIT は yfinance に無いことが多く、自動的にスキップされる
- 通知は判断材料であって推奨ではない。最初の1〜2ヶ月は通知だけ受けて、的中率を記録してから使う
